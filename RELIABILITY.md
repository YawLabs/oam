# Reliability Program — the scorecard is the product

"Fewer bugs than Bun" must be a dashboard, not a slogan. This file defines what oam measures,
publishes, and gates releases on. Dashboards live at https://oam.sh/reliability and
https://oam.sh/compat once public; until then the same jobs run in CI.

## Published metrics

| Metric | Definition | Gate |
|---|---|---|
| Node-suite pass rate | Node.js's own test suite, run per-module in CI, live per-module dashboard | ratchet-only (never regresses) |
| ECMA-429 / WPT conformance | WinterTC Minimum Common Web API + relevant WPT subset | ratchet-only |
| Crash rate | crashes per million process-hours, from strictly opt-in, minidump-signature-only telemetry (no user code, no paths; privacy policy published before the first byte is collected) | published trend |
| Soak | 30-day continuously-running workloads (HTTP serve, agent loop, install churn); RSS flatness | regression fails release |
| Behavior changes in patch releases | counted by the API-diff bot | target 0, published |
| `unsafe` count | per-crate ratcheting ceiling (may only go down), `oam_engine` quarantined; compared against deno_core. Per-site justification is compiler-enforced on every crate by clippy rather than counted -- private unsafe fns and `unsafe extern` blocks are not covered by any lint and rest on review | regression fails build |
| Benchmarks | the `oam-bench` suite vs Bun/Node/Deno on >=2 hardware classes incl. Windows ARM64; manifests + raw data + flamegraphs attached; competitor-best-config rule | marketing may cite only CI-reproduced numbers |

## Semver policy

- **Pre-1.0:** every release ships a public behavior-change log: every observable change
  (API, CLI flags, defaults, error text) enumerated, generated by the API-diff bot plus
  human annotation. The discipline starts now; the hard gate starts at 1.0.
- **From 1.0 (mechanical semver):** a versioned snapshot of the public surface (runtime
  `.d.ts`, CLI flags, behavior matrix including defaults) is checked in; CI diffs every PR
  against it. Any observable change requires a major version. No exceptions, no "minor
  cleanup" carve-outs — those are how trust dies in patch releases.
- **N-1 gate:** every release must pass the previous release's entire test suite. Tests may
  not be modified in the same PR as the implementation they gate (AI-POLICY.md gate 3).

## LTS

Committed now, effective at 1.0: every 1.x line is maintained for 24 months from its 1.0.
Details (cadence of LTS lines after 2.0) will be specified before 1.0 ships.

## Platform policy

Tier-1 (every PR gated): windows-x64, windows-arm64, macos-x64, macos-arm64, linux-x64-gnu,
linux-arm64-gnu. "Tested on Windows before it ships, not after."

## Fuzzing

Continuous fuzzers on: the Rust<->V8 ops boundary, lockfile/package.json parsers, HTTP
parsing, and the TS stripper. OSS-Fuzz application at public launch. Trophies published.

## oam's own supply chain

SLSA provenance + reproducible builds for all release artifacts from the first public release.
Binaries are code-signed (Windows Authenticode) and notarized (macOS) before any public
distribution. The installer and update channel serve exclusively from oam.sh, with checksums
pinned in-repo; 0am.sh is defensively registered and only redirects.
